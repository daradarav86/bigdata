# retail.csv — 프로젝트용

관심 진로: 유통, 경영, 마케팅, 회계, 전자상거래, 물류

가공본 6,103행 × 7열. 이 파일은 분석·시각화 전 학생이 전처리하는 자료입니다.

## 원자료 및 준비 기준
Chen, D. (2015). Online Retail. UCI. https://doi.org/10.24432/C5BW33

https://archive.ics.uci.edu/dataset/352/online+retail

2011년 1~11월, 국가×월×거래상태(취소/기타/설명결측)별 최대20개 거래명세를 고정 난수42로 추출. 취소·음수·0단가·설명 결측 유지. 고객 ID 제외. 국가·월 집계 전 원명세 형태.

## 열 설명
| 열 | 뜻·단위 |
|---|---|
| `InvoiceNo` | 주문번호, C로 시작하면 취소 |
| `StockCode` | 상품코드 |
| `Description` | 상품설명, 빈칸 존재 |
| `Quantity` | 명세수량, 음수는 취소/반품 등이므로 확인 |
| `InvoiceDate` | 거래시각 문자열 |
| `UnitPrice` | 단가GBP |
| `Country` | 고객 거주국가 |

## 수업용 가공
전처리 연습을 위해 원자료를 다음과 같이 바꿨습니다.
- 빈칸: `Quantity` 61개, `UnitPrice` 61개
- 있을 수 없던 값(→ 모두 빈칸으로 바꿈): `UnitPrice` -5.0 31개
- 날짜가 아니던 값(→ 빈칸으로 바꿈): `InvoiceDate`의 `2011-02-30 10:00:00` 15개, `not_a_date` 15개

**현재 파일에는 결측치(빈칸) 외의 이상값이 없습니다.** 범위 밖 값은 모두 빈칸으로 바꿨으므로 전처리는 `isnull().sum()` → `dropna()`/`fillna()`만으로 끝납니다. 아래 빈칸 개수에 바꾼 값이 더해져 실제 빈칸은 더 많습니다.

`Description`의 빈칸과 취소(C로 시작하는 주문번호)·음수 수량·0 단가는 원자료 그대로입니다. 음수 수량은 취소·반품으로 순매출에서 빠지는 값이므로 이상값이 아닙니다.
